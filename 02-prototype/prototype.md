## What it demonstrates

This is a prototype of a dashboaard to be used by a PM to guide the prioritization of bug fixes for the next spint that are being reported.

The dashboard uses Juno AI PM to gather the data from Slack, Notion, and Jira to find the reported bugs, combine similar bugs, report bugs that are currently being worked, report the department the bug belongs to, and finally prioritize and rank the nessecity of the fix.

_____

## Debrief

- **What worked:**
  My teammates said that as a whole the prototype works well. The dashboard gives an overview of the reported bugs and shows how many were merged. It shows the bugs that were removed from the prioritization list because it is being worked on. And it breaks down the remaining bugs into a prioritized list based on four items:
  - How bad the impact is
  - How likely it is to hit customers
  - How soon it needs action
  - How many independent sources reported the same bug
 
  It also gives an area (section 4) of possible gaps or missing information that needs to be verified before moving forward. And a area (section 5) of recommended next steps before approval.

- **What broke / felt like a toy:**
  I'm not sure that I can say anything really broke. I did notice that the report needed some headers and a few labels to help guide the use of the tool.

  One of my teammates stated that the dashboard looked a little busy. But I'm not sure I agree with that asumption, only becasue the person that will be using the dashboard would be the PM and he/she would know what they were looking at.
  
- **What I'd change next pass:**
  I have already added some hearders and labels, but I think I could add a few more for clarification.
